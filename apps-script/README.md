# Подписка на новости → Google Таблица

Форма подписки на главной странице (`site/index.html`, блок `#newsletter`) отправляет адрес в веб-приложение Google Apps Script. Скрипт добавляет строку в Google Таблицу. Платных сервисов и отдельной CRM нет.

```
Сайт (GitHub Pages) ──POST──▶ Apps Script /exec ──▶ Google Таблица «Подписчики»
                     ◀─JSON── (через 302 на googleusercontent.com)
```

## Файлы

| Файл | Что это |
|---|---|
| `apps-script/Code.gs` | Серверный код. Его нужно вставить в редактор Apps Script. |
| `apps-script/appsscript.json` | Манифест: часовой пояс Europe/Tallinn и настройки веб-приложения. |
| `site/js/newsletter-config.js` | **Единственное место**, где хранится URL `/exec`. |
| `site/js/main.js` | Логика формы (блок `setupNewsletter`). |
| `apps-script/tests/` | Локальные тесты. На сайт они не влияют. |

## Формат таблицы

Лист **«Подписчики»**, первая строка ровно такая:

| A | B | C | D |
|---|---|---|---|
| Дата подписки | RU | EN | ET |

Одна подписка — одна новая строка. Дата и время (часовой пояс Таллина) пишутся в A. Email пишется только в колонку языка, на котором посетитель смотрел сайт в момент отправки. Две другие ячейки остаются пустыми. Пример строки для EN: `27.09.2026 14:05 | (пусто) | anna@example.com | (пусто)`.

- Если заголовки не совпадают, скрипт ничего не пишет, а посетитель видит «ошибка, адрес не сохранён».
- Тот же адрес на том же языке новую строку не создаёт, но посетитель всё равно видит обычное «Спасибо». Сравнение идёт без учёта регистра и пробелов по краям.
- Тот же адрес на другом языке создаёт новую строку.

## Настройка по шагам

### 1. Превратите XLSX в Google Таблицу

В ссылке, которую вы прислали, есть `rtpof=true`. Это значит, что на Диске лежит **файл Excel, а не Google Таблица**. Apps Script не может записывать в `.xlsx`, поэтому файл нужно преобразовать:

1. Откройте файл на Google Диске.
2. Выберите **Файл → Сохранить как Google Таблицы**. Google создаст новый файл с новым ID.
3. Откройте новый файл. Его ID — это часть адреса между `/d/` и `/edit`:
   `https://docs.google.com/spreadsheets/d/`**`ЭТО_И_ЕСТЬ_ID`**`/edit`
   Старый ID `1Uq-xuNnJEktALyBHD-gI4i4eado-2MAh` принадлежит XLSX-файлу. **Для скрипта он не подходит.**
4. Проверьте, что лист называется точно `Подписчики`, а в первой строке стоят `Дата подписки`, `RU`, `EN`, `ET`. Лишних колонок, например «Язык» или «Имя», быть не должно.
5. **Доступ к таблице не открывайте.** Кнопка «Настройки доступа» должна показывать «Доступ ограничен». Веб-приложение работает от вашего имени, и публичный доступ ему не нужен.
6. Выберите **Файл → Настройки → Часовой пояс → (GMT+02:00) Tallinn** и нажмите «Сохранить».

Исходный `.xlsx` можно удалить с Диска или оставить. В репозиторий его класть нельзя: `.gitignore` уже не пускает туда `*.xlsx`, `*.csv` и похожие файлы.

### 2. Откройте Apps Script и вставьте код

1. В новой Google Таблице выберите **Расширения → Apps Script**.
2. Удалите всё содержимое `Код.gs` (или `Code.gs`) и вставьте туда содержимое `apps-script/Code.gs` из репозитория. Сохраните (💾 или Ctrl+S).
3. Откройте **Настройки проекта** (шестерёнка слева):
   - поставьте галочку **«Показывать файл манифеста appsscript.json в редакторе»**;
   - в поле **«Часовой пояс»** выберите `(GMT+02:00) Tallinn`.
4. Вернитесь в **Редактор**, откройте `appsscript.json`, замените содержимое на `apps-script/appsscript.json` из репозитория и сохраните.

### 3. Задайте Script Properties

1. Выберите **Настройки проекта → Свойства скрипта → Добавить свойство скрипта**.
2. Заполните поля:
   - Свойство: `SPREADSHEET_ID`
   - Значение: ID **новой** Google Таблицы из шага 1.3
3. Нажмите **«Сохранить свойства скрипта»**.

### 4. Проверьте настройку и дайте разрешения

1. В редакторе выберите в выпадающем списке функцию `checkSetup` и нажмите **Выполнить**.
2. Google попросит разрешения. Выберите свой аккаунт. Если появится окно «Приложение не проверено», нажмите **Дополнительно → Перейти в проект (небезопасно)** → **Разрешить**. Это ваш собственный скрипт; он просит доступ только к таблицам.
3. Внизу, в «Журнале выполнения», должно появиться: `Всё в порядке: таблица доступна, заголовки и часовые пояса верны.` Если там список проблем, исправьте их и запустите `checkSetup` ещё раз. Эта функция в таблицу ничего не пишет.

### 5. Разверните веб-приложение

1. Нажмите **Начать развертывание → Новое развертывание**.
2. Нажмите шестерёнку рядом с «Выберите тип» и выберите **Веб-приложение**.
3. Заполните поля:
   - Описание: например, `Подписка v1`
   - **Запуск от имени: Я (ваш email)**
   - **У кого есть доступ: Все** (именно «Все», а не «Все с аккаунтом Google»: посетителю не нужно входить в Google)
4. Нажмите **Развернуть** и скопируйте **URL веб-приложения**. Он заканчивается на `/exec`.

### 6. Вставьте URL в сайт

Откройте `site/js/newsletter-config.js` и вставьте URL:

```js
window.SARLE_NEWSLETTER = {
  endpoint: 'https://script.google.com/macros/s/XXXXXXXX/exec'
};
```

Закоммитьте изменение и отправьте его в ту ветку, из которой публикуется GitHub Pages. Через 1–2 минуты сайт обновится.

Этот URL публичный по своей природе: он виден в коде любой страницы, и это нормально. Ни API-ключей, ни токенов, ни паролей в сайте нет и быть не должно.

Пока `endpoint` пустой, форма пишет «Подписка временно недоступна» и ничего не сохраняет. Ложного «Спасибо» она не показывает.

### 7. Боевая проверка (после развёртывания)

Чтобы не засорять рабочую таблицу тестовыми строками:

1. Сделайте копию таблицы (**Файл → Создать копию**) и временно укажите её ID в `SPREADSHEET_ID`. Свойства скрипта применяются сразу, переразвёртывать не нужно.
2. На сайте подпишитесь по разу на EN, RUS и EST. Проверьте, что каждая строка легла в свою колонку, а дата стоит в формате `дд.ММ.гггг ЧЧ:мм` по таллинскому времени.
3. В браузере откройте DevTools → Network. Запрос к `script.google.com` должен вернуть JSON `{"ok":true,"code":"ok","requestId":"..."}`.
4. Верните в `SPREADSHEET_ID` ID рабочей таблицы.

### Как обновлять скрипт после изменений

Если вы поменяли `Code.gs`, одного сохранения мало: веб-приложение продолжит работать на старой версии.

1. Нажмите **Начать развертывание → Управление развертываниями**.
2. Выберите текущее развертывание и нажмите ✏️ (изменить).
3. В поле **Версия** выберите **Новая версия** и нажмите **Развернуть**.

URL `/exec` при этом **не меняется**. Не выбирайте «Новое развертывание»: оно выдаст новый URL, и его придётся заново вставлять в `site/js/newsletter-config.js`.

Если поменять только Script Properties, переразвёртывать не нужно.

## Как это устроено

**Сетевой обмен.** Форма отправляет `fetch` POST с телом `application/x-www-form-urlencoded`. Это «простой» CORS-запрос без preflight-запроса `OPTIONS`, который Apps Script не умеет обрабатывать. Apps Script отвечает редиректом 302 на `script.googleusercontent.com`. Этот адрес отдаёт JSON с заголовком `Access-Control-Allow-Origin: *`, поэтому браузер разрешает сайту прочитать ответ. Cookies не отправляются (`credentials: 'omit'`), так что вход посетителя в Google ни на что не влияет.

- `mode: 'no-cors'` и iframe не используются. Успех показывается **только** если сервер вернул JSON с `ok: true` и тем же `requestId`, который сгенерировала форма.
- Если ответ не читается, показывается ошибка, а введённый адрес остаётся в поле:
  - не пришёл CORS-заголовок;
  - сервер вернул HTML с ошибкой;
  - обрыв сети;
  - тайм-аут 20 секунд.
- Повторная отправка безопасна: если первая попытка всё-таки записалась, повтор просто найдёт дубль.

**Язык.** Форма берёт язык из переключателя сайта (EN / EST / RUS) в момент отправки, а не из языка браузера. Переключение без перезагрузки учитывается, и сообщения формы тоже меняют язык.

- Коды сайта и стандартные коды языка сводятся к трём значениям:

  | Что приходит | Колонка |
  |---|---|
  | `EST`, `et`, `et-EE` | ET |
  | `RUS`, `ru`, `ru-RU` | RU |
  | `EN`, `en-GB`, `en-US` | EN |

- Если язык неизвестен, форма показывает ошибку и ничего не отправляет.
- Сервер принимает только `RU`, `EN` и `ET`.

**Защита.**

- Email проверяется и в браузере, и на сервере:
  - длина не больше 254 символов;
  - строгий формат;
  - первый символ — буква или цифра, поэтому адрес не может начинаться с `=`, `+`, `-` или `@` (защита от формул);
  - в ячейку адрес записывается с текстовым форматом.
- Согласие на рассылку проверяется на сервере.
- Скрытое поле-ловушка (honeypot): если оно заполнено, сервер отвечает «успехом», но ничего не пишет.
- Форма не отправляет чаще одного раза в 4 секунды, а сервер принимает не больше 30 заявок в минуту на всю форму.
- Проверка дубля и запись выполняются под `LockService`, внутри `try/finally`, чтобы параллельные запросы не создали дубли.

Это **базовая** защита, а не полноценная защита от ботов. Если спам всё-таки появится, следующий шаг — капча (например, Cloudflare Turnstile, у неё есть бесплатный тариф).

**Приватность.**

- Веб-приложение только добавляет строки и никогда не возвращает содержимое таблицы.
- Посетитель не узнаёт, был ли адрес подписан раньше: ответ одинаковый в обоих случаях.
- Внутренние ошибки попадают только в журнал выполнения Apps Script. Посмотреть его можно в разделе **Выполнения** слева в редакторе.

## Перед реальной рассылкой

Сейчас реализован **только сбор заявок**. Перед тем как отправлять письма, нужна отдельная настройка:

- способ отправки: сервис рассылок или Gmail с учётом его дневных лимитов;
- ссылка «Отписаться» в каждом письме и учёт отписавшихся;
- желательно подтверждение адреса письмом (double opt-in) и хранение даты согласия.

Этого сейчас нет.

## Локальные тесты

```bash
node --test apps-script/tests/code.test.js                                   # сервер (Code.gs)
NODE_PATH=$(npm root -g) node --test apps-script/tests/e2e.test.js           # браузер, нужен playwright
```

- `code.test.js` запускает настоящий `Code.gs` с поддельными сервисами Google в памяти.
- `e2e.test.js` открывает сайт в Chromium и отправляет форму на локальную имитацию Apps Script. Имитация повторяет схему Google «302 → JSON с CORS-заголовком» и выполняет тот же `Code.gs`.

Настоящие серверы Google эти тесты **не проверяют**. Это проверяется один раз после развёртывания (шаг 7).
